# gtm-revops-ai-automations (plugin)

A Claude Code plugin for Revenue Operations analysts. Ships a **Model Context Protocol server** exposing four tools against a synthetic sales-pipeline dataset, plus a skill that orchestrates them into a Monday-morning pipeline review.

## Primitives in scope

- ✅ Claude Code **plugin** (the install unit)
- ✅ **Model Context Protocol server** — the new primitive introduced here. Exposes 4 tools over both standard-input/output and streamable-HTTP transports.
- ✅ Claude Code **skill** (`gtm-revops-pipeline-review`) — orchestrates tool calls and assembles the markdown review
- ✅ Python program (`gtm-revops-seed`) — generates the 300-row synthetic opps fixture
- ❌ No slash command (multiple distinct tools; not a single-shortcut shape — natural language is the right entry)
- ❌ No hooks (no governance requirement here — see Plugin 4 for that primitive)

This plugin demonstrates the cleanest "Claude needs to touch a system" shape: many related operations, structured arguments, reusable across clients.

## What the four tools do

| Tool | Returns |
| --- | --- |
| `list_open_opps(stage?)` | Open opportunities, optionally filtered by stage |
| `check_data_quality()` | Pipeline-hygiene issues (missing close dates, negative amounts, orphan accounts) |
| `roll_up_pipeline(group_by)` | Open pipeline value and count, grouped by stage or owner |
| `flag_stale_opps(days=30)` | Open deals with no activity in the last N days, sorted oldest-first |

## Quickstart

```bash
# From the monorepo root
uv sync

# Generate the synthetic data (only needed once)
uv run --package gtm-revops-ai-automations gtm-revops-seed

# Smoke-check the server (boots, registers all 4 tools, exits 0)
uv run --package gtm-revops-ai-automations gtm-revops-mcp --self-check

# Inspect tools interactively in the official MCP inspector UI
uv run mcp dev gtm-revops-ai-automations/src/gtm_revops/mcp.py
```

## Registering the server in Claude Code

There are two ways to make the tools callable from a Claude Code session:

### Option A — Standard input/output (Claude Code starts the server for you)

Add to your project's `.claude/settings.json` (or `.claude/settings.local.json`):

```json
{
  "mcpServers": {
    "gtm-revops": {
      "command": "uv",
      "args": [
        "run",
        "--package",
        "gtm-revops-ai-automations",
        "gtm-revops-mcp",
        "--stdio"
      ]
    }
  }
}
```

Restart Claude Code. The server boots as a child process automatically.

### Option B — Streamable HTTP (the "remote" demo)

In one terminal, start the server as an HTTP service:

```bash
uv run --package gtm-revops-ai-automations gtm-revops-mcp --http --port 8765
```

Then in your project's `.claude/settings.json`:

```json
{
  "mcpServers": {
    "gtm-revops": {
      "url": "http://localhost:8765/mcp"
    }
  }
}
```

Open Claude Code in a separate workspace and the running HTTP server is reachable. Same wire protocol as Option A — only the connection mechanism differs.

## What to ask once it's registered

In a Claude Code session with the server registered:

- *"How's the pipeline looking?"* — full Monday-morning review (roll-up + data quality + stale deals)
- *"Roll up the pipeline by owner"* — single-cut roll-up
- *"What data quality issues are in the pipeline?"* — hygiene check only
- *"Show me deals stuck for more than 45 days"* — stale-deal report with custom threshold

The `gtm-revops-pipeline-review` skill auto-routes on those phrasings via its description.
